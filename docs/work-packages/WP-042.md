# WP-042: Prod auf den Mac Studio umziehen

## Ziel
prod läuft auf dem Mac Studio (`areuss-studio.local`), das MacBook ist nur noch Entwicklungsrechner. `npm run release` und alle `prod:*`-Befehle werden weiter auf dem MacBook aufgerufen und steuern den Studio per SSH (D-036).

## Scope
**Drin:**
- Checkout von `main` auf dem Studio (`~/poker`, HTTPS-Clone des öffentlichen Repos, nur lesend), `.env.prod` dort
- `prod:*`-Skripte laufen per SSH auf dem Studio; Smoke- und E2E-Test vom MacBook über eine SSH-Portweiterleitung
- `release`: Merge dev → main in einem temporären Worktree auf dem MacBook, Push, Pull + Neustart auf dem Studio, Prüfung, Rollback-Hinweis für den Studio
- `prod:setup` richtet den Checkout auf dem Studio ein (ersetzt den Prod-Worktree, D-017)
- Umzug der Daten: Backup auf dem MacBook → Restore auf dem Studio, Tunnel umziehen, MacBook-prod und Prod-Worktree entfernen
- README: Admin-Sonderfunktionen (fremde Karten sehen, eigene Karten neu ziehen)

**Nicht drin:**
- Node auf dem Studio (der Studio braucht nur git, Docker und bash)
- Änderungen an `compose.prod.yml`, Backups oder Tunnel-Konfiguration

## Akzeptanzkriterien
- [x] `npm run prod:status` auf dem MacBook zeigt den Zustand des Studio-prod (alle Container healthy, Backup, Health lokal und öffentlich)
- [x] `npm run prod:smoke` und `npm run prod:e2e` laufen vom MacBook gegen den Studio
- [x] Daten vom MacBook-prod auf dem Studio wiederhergestellt (Benutzerzahl gleich), beide Domains erreichbar
- [x] Auf dem MacBook laufen keine `poker-prod`-Container mehr, der Prod-Worktree ist entfernt
- [x] `release-verify.sh` nennt Rollback-Befehle für den Studio, Test angepasst
- [x] D-036, WORKFLOW, OPERATIONS, ARCHITECTURE, README aktualisiert
