# WP-024: Feedback-Button

## Ziel
Spieler können aus der App heraus Feedback schicken (Bug, Idee, Sonstiges); es landet in der Datenbank und Arthur kann es lesen.

## Scope
**Drin:**
- Migration: Tabelle `feedback` (id, user_id, Kategorie bug/idee/sonstiges, Text max. 2000 Zeichen, Kontext: aktuelle Seite/Tisch-ID, App-Version, User-Agent, Ausrichtung; Status neu/gelesen/erledigt; created_at)
- `POST /api/feedback` nur für eingeloggte Spieler, Rate-Limit (z. B. 5 pro Stunde)
- Feedback-Button in der App (Menü und Tisch-Menü), kleines Formular mit Kategorie und Text, Bestätigung
- Admin-Ansicht `/admin/feedback` (nur `is_admin`): Liste, Filter nach Status, Status ändern
- CLI `admin:feedback` zum schnellen Auflisten im Terminal

**Nicht drin:**
- Screenshots/Anhänge, E-Mail-Benachrichtigung

## Akzeptanzkriterien
- [ ] Eingeloggter Spieler kann Feedback senden, es steht danach mit Kontext in der DB
- [ ] Nicht eingeloggt → 401; zu langer Text oder ungültige Kategorie → 400; Rate-Limit greift
- [ ] Nur Admins sehen und bearbeiten Feedback (API und UI)
- [ ] Feedback wird bei Account-Löschung (WP-022) mit anonymisiert, nicht gelöscht
- [ ] Integrationstests für API, Komponenten-Test für das Formular

## Tests
Integrationstests gegen Test-DB, Komponenten-Tests (Vitest + Testing Library).
