# WP-011: Game-Server: WebSocket-Protokoll und Tische

## Ziel
Mehrere Spieler können über WebSockets an einem Tisch eine komplette Runde spielen; der Server ist autoritativ (D-003).

## Scope
**Drin:**
- Protokoll mit typisierten Nachrichten (gemeinsames Paket oder `packages/engine/protocol`), Validierung aller eingehenden Nachrichten
- Tisch erstellen (öffentlich/privat mit Link-Code), Platz nehmen/verlassen, Start durch Ersteller, Zuschauen
- Aktionen an die Engine weiterreichen, Zustand pro Spieler gefiltert senden (fremde Karten nie vor dem Showdown)
- Heartbeat alle 30 s, Origin-Prüfung gegen `PUBLIC_ORIGIN` (D-014)
- Lobby-Liste offener Tische

**Nicht drin:**
- Timer, Zeitbank und Reconnect (WP-012)
- Persistenz der Hand-Historie (WP-013)

## Akzeptanzkriterien
- [x] Integrationstest: 3 Clients spielen eine Runde bis zum Sieger
- [x] Kein Client erhält je fremde Hole Cards vor dem Showdown (Test prüft alle gesendeten Nachrichten)
- [x] Ungültige oder nicht zugelassene Nachrichten werden abgelehnt, ohne den Tisch zu stören
- [x] Verbindung über den Vite-Proxy (dev) und den Prod-Reverse-Proxy funktioniert

## Tests
WebSocket-Integrationstests mit echten Verbindungen gegen einen Testserver.
