# WP-003: Prod-Setup und Cloudflare-Tunnel vorbereiten

## Ziel
main lässt sich mit einem Befehl als Produktionsumgebung bauen und starten; der Tunnel zu poker.arthur-reuss.de braucht nur noch das Token.

## Scope
**Drin:**
- `compose.prod.yml`, Projektname `poker-prod`, eigene DB und Volumes
- Multi-Stage-Dockerfiles (Build → schlankes Runtime-Image)
- Web-Container (statischer Build + Reverse-Proxy für `/api` und `/ws`) auf 127.0.0.1:4320, Server intern (4321 nur lokal zum Debuggen)
- `cloudflared`-Service mit `TUNNEL_TOKEN` aus `.env.prod` (nicht im Git)
- Restart-Policies und Healthchecks
- Skripte `prod:up`, `prod:down`, `prod:logs`, `release` (check → merge dev→main → prod:up)
- Anleitung: Tunnel im Cloudflare-Dashboard anlegen, Public Hostname `poker.arthur-reuss.de` → `http://web:8080`

**Nicht drin:**
- Tunnel tatsächlich live schalten (WP-023)
- Backups (WP-021)

## Akzeptanzkriterien
- [x] `npm run prod:up` startet ohne Tunnel-Token lokal unter http://localhost:4320 (cloudflared-Service per Profil abschaltbar)
- [x] WebSocket-Upgrade funktioniert durch den Reverse-Proxy
- [x] Prod-Images enthalten keine Dev-Abhängigkeiten und keine Quell-Maps mit Secrets
- [x] dev und prod können gleichzeitig laufen, ohne sich zu stören
- [x] `docs/OPERATIONS.md` beschreibt Start, Stopp, Release und Tunnel-Einrichtung

## Tests
Smoke-Skript, das `prod:up` startet und `/api/health` sowie einen WS-Handshake über 4320 prüft.
